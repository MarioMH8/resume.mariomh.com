# Conventions

## Runtime and package management

Use Bun 1.4.4 for installation, scripts, tests and builds. The lockfile is `bun.lock`. The repository uses Bun workspaces with a single workspace: `resume`.

## Package names

The published package is `@mariomh8/resume`. The private site package is `resume.mariomh.com` and is never published. The package lives in `resume/` and is published to GitHub Packages.

## TypeScript

The repository uses TypeScript 6.0.3 with `@hexadrop/tsconfig` 0.0.5. The root `tsconfig.json`:

- Extends `@hexadrop/tsconfig`.
- Maps `@resume` to `./resume/src/index.ts`, which also re-exports the schema types.
- Maps the site aliases `@assets`, `@components`, `@config`, `@features`, `@icons` and `@layout`.
- Uses `types: ["bun"]`.
- Loads the `@astrojs/ts-plugin` plugin.
- Includes the whole repository and excludes `node_modules` and `**/dist/*`.

## Linting

ESLint 10.14.0 runs with `@hexadrop/eslint-config` 1.3.1 in flat config. `eslint.config.js` awaits `hexadrop(...)`, passes the root TypeScript project and configures `@typescript-eslint/parser` for `.cjs`, `.js` and `.mjs` so the import rules can read the published `.mjs` files.

Use `bun run lint:fix` while working and `bun run lint:ci` to validate without writing. The lint script uses the content-based ESLint cache.

## Building

`resume/` uses `tsdown` 0.23.7:

- ESM-only `.mjs` output.
- `.d.mts` declarations generated by `resume/scripts/build-assets.ts`.
- Neutral platform and source maps.
- `dist/resume.json` and `dist/schema.json` generated from Zod.
- Subpath exports for `./resume.json` and `./schema.json`.

Do not add a `prepublishOnly` build. The release workflow builds the package once with its `build-command`, and the same output is published.

## Comments

Write code that explains itself. Add a comment only for a non-obvious constraint, workaround or external behavior that names, types and tests cannot express. Do not narrate what the code does. Put design rationale in a task guide, not inline.

## Repository configuration

`package.json` is the source of truth for scripts and dependencies. Keep `bun.lock` updated with Bun when dependencies change. Commit messages follow Conventional Commits through `commitlint.config.ts`.

`.idea/` is tracked in this repository and must stay tracked. Do not remove or ignore it.

## Registry and dependencies

`@mariomh8/resume` declares `publishConfig.registry` with `https://npm.pkg.github.com`. The repository `.npmrc` only declares the `@mariomh8` scope; never commit a token.

The site pins the design system packages to published versions. The local `@mariomh8/resume` is consumed through `workspace:*`; the published manifest is independent of the workspace protocol.

Authentication rules:

- Local development uses a classic personal access token with `read:packages`.
- CI uses the `PACKAGES_TOKEN` Actions secret because the design system packages are published from `brand.mariomh.com`.
- Renovate uses the `RENOVATE_PACKAGES_TOKEN` secret from its own `renovate.json` configuration, not from GitHub Actions.

See [Development](development.md) for the local authentication steps.
